# Codex Home Instructions

Treat this repository as the local Codex home. It may contain persistent memory, dialogue context, skills, helper code, and related working notes.

Project conventions:

- All documents and code in this repository must be written in English.
- Code comments should be minimal and used only when they explain how or why something works, not what the code plainly does.
- Use Python for repository scripts.
- Manage Python dependencies and script execution with `uv`. If a script needs a missing library, install it with `uv`.
- Commit messages must be one-line messages.
- Commit messages must not mention AI.
- When asked to preserve session learnings, wrap up work, update memory, or create reusable procedures, use the session memory review workflow before committing.
- When a session produces critical durable knowledge, run the LLM-wiki lifecycle before closing the task. Critical knowledge includes validated benchmark results that change operational choices, production or incident root causes, safety constraints, architecture or cross-project contracts, and recurring high-impact procedures. Capture a raw local session note, promote approved knowledge to the appropriate wiki page or prepare a draft when approval is absent, link its sources, and run wiki lint. Do not leave critical knowledge only in chat, `tmp/`, references, or project profiles.
- Durable textual research evidence must be stored in a `research/<YYYY-MM-DD-project-topic>/` bundle that follows `research/README.md`. Preserve safe canonical records, derived summaries, provenance, checksums, validation output, and reproducibility scripts. Keep audio, raw environment or integration dumps, unreviewed patient-derived transcripts, and generated reports under the bundle's gitignored `local/` directory. Run `uv run python scripts/evidence_gate.py <bundle>` before committing research evidence.
- Create and maintain diagnostic cases only under `incidents/<YYYY-MM-DD-system-topic>/` in this repository, following `incidents/README.md`. Never create a case archive in a product repository. Commit only privacy-reviewed reports, manifests, bounded sanitized text, knowledge dispositions, safe encrypted-object receipts, and public encryption recipients; keep raw logs, transcripts, identifiers, environment snapshots, screenshots, audio, archives, working notes, credentials, and private identities under the case's gitignored `local/` directory or an approved secrets store. The only instance age-key registry permitted in Git is `incidents/PUBLIC-AGE-RECIPIENTS.yaml`; the clean starter may additionally contain its empty `.example.yaml` scaffold source. Both files may contain public `age1...` recipients only; never add an age private identity, vault secret, OAuth token, recovery credential, or per-case usage list. Committed restore receipts are the source of truth for recipient usage; derive the inverse mapping with `uv run python scripts/evidence_offload.py recipient-usage`. Use active registry IDs rather than copying public recipients into commands. Use the `incident-evidence-offload` skill whenever raw case evidence must be encrypted, uploaded, restored, rotated, or evaluated for source cleanup. Evidence that must survive local retention requires a locally encrypted, content-verified second copy with a stable provider object ID and successful restores by distinct primary and escrow keys before `evidence.state` may become `offloaded`. A product repository may retain only a minimal sanitized regression fixture owned by an automated test and linked to the canonical case UUID. Never delete a legacy evidence source until the second copy, restore gates, cross-links, and replay dependencies have been verified and the user explicitly approves deletion. Run `uv run python scripts/incident_case.py validate` before committing case records.
- Before studying or changing code in a project repository, fetch remote refs and update the local branch to the latest upstream state when this can be done without overwriting local uncommitted work. If the worktree is dirty or local commits diverge, inspect and report the state before relying on local code as current.
- Do not store developer-specific absolute home-directory paths in memory, project profiles, skills, or references. Use neutral variables defined by `.env.template`, project profiles, or local instance instructions instead.
- Store local developer path values in gitignored `.env`; keep `.env.template` as the committed variable contract. Load `.env` before running commands that depend on those variables.
- If `AGENTS.local.md` exists, read it after this file for instance-specific rules, variable names, project families, or local overlays. If the current agent runtime does not auto-load it, inspect it manually before using local context.
- When a user asks to initialize or bootstrap this CodexHome instance, run `uv run python scripts/bootstrap_instance.py` from the repository root. Bootstrap creates `.env` from `.env.template` and sets `CODEX_HOME` to the current checkout path. Do not infer or discover `PROJECTS_ROOT`; pass `--projects-root <path>` only when the user explicitly provides that value before the first bootstrap run. If `PROJECTS_ROOT` is still a placeholder after bootstrap, ask the user which project root to use; when they provide it, run `uv run python scripts/bootstrap_instance.py --env-only --projects-root <path>`.
- When a user asks to publish an initialized CodexHome instance, ask for the empty private Git remote URL if it was not provided. Use `uv run python scripts/publish_instance.py --instance-remote <url> --dry-run` to show the plan, then run with `--push` only when the user asked to push. Do not create GitHub or GitLab repositories automatically unless the user explicitly asks for repository creation.

Repository layout:

- `AGENTS.md` stores global agent behavior, repository conventions, and workflow rules.
- `AGENTS.local.md`, when present, stores instance-specific rules that should not be copied into a clean starter repository.
- `.codex/skills/` stores reusable procedures. Each real skill should live in its own directory with a `SKILL.md` entrypoint.
- `projects/` stores project profiles, links between related projects, local paths, commands, and project-specific context.
- `incidents/` stores canonical diagnostic cases with committed safe records and gitignored local evidence.
- `research/` stores per-investigation evidence bundles with committed safe evidence and gitignored sensitive or regenerable local artifacts.
- `references/` stores longer background material, examples, and documents that skills or instructions may reference.
